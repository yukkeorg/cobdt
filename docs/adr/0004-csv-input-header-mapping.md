# CSV データ入力はヘッダ名で対応づけ、位置順の `data` とは非対称にする

`create --data-csv <data.csv>` で、YAML の `data` の代わりに CSV ファイルから値を取り込めるようにした。
既存システムや表計算が吐く、集団項目で構造化された素朴な固定長表データを大量投入する用途に応えるためである。

このとき、CSV の列と `record` の項目の対応づけを**ヘッダ名（列名）で行い、位置順にしない**と決めた。
YAML の `data` が `record` をフラット化した**位置順**で値を並べるのとは非対称である。

位置順案（`data` と同じ規則を CSV にも適用）も検討した。利点はメンタルモデルが 1 つで済み、FILLER も
普通に 1 列を占め、同名項目があっても順序で解決できることである。しかし退けた。CSV の現実の供給元
（表計算・DB エクスポート）は列名つきヘッダを持ち、列順が `record` 定義と一致する保証がなく、cobdt では
使わない余計な列も混ざる。位置順では列の並べ替え・省略・余計な列に弱く、1 列ずれると以降のバイトが
すべて壊れる固定長データでは事故が致命的になる。ヘッダ名なら列順非依存で、列名のタイプミスや定義ずれを
未知列としてエラーで早期に検出できる。

ヘッダ名対応に伴い、いくつかの帰結を受け入れた。

- **FILLER は CSV から入力できない**。FILLER は名前を持たず、ヘッダ名で指せないためである。CSV に列が
  ない項目（FILLER・名前つきを問わず）は `value`（既定は数値 `ZERO`／それ以外 `SPACE`）で埋める。
  「列がある＝上書き、列がない＝初期値」という一貫した規則にした。
- **同名の葉は集団名で修飾して一意化する**。葉名が一意なら単独で、曖昧なときだけ `GROUP.LEAF` のドット
  修飾を要求する（COBOL の修飾参照 `LEAF OF GROUP` に相当）。位置順なら不要だった曖昧性解決だが、名前を
  キーにする以上必要になる。
- **入れ子・マップを要する構文は CSV の対象外**。OCCURS（入れ子リスト）・再定義（解釈の選択）・raw セル
  （マップ）はフラットな CSV では表現できない。これらを含む `record` に `--data-csv` を指定すると、黙って既定で
  埋めず load 時にエラーで止める（[ADR 0002](0002-import-copybook-strict-subset.md) と同じ fail-loud
  方針を、未対応構文だけでなくデータ源の構造にも及ぼす）。表意定数だけは裸のスカラで書けるため `data` と
  同様に解釈する。

## Consequences

- CSV と YAML `data` で、セルの意味（表意定数解釈・空文字の埋め）は揃えるが、**対応づけの軸（名前 vs 位置）
  だけが異なる**。同じ値でもファイル形式によって書き方が変わる点はドキュメントで明示する。
- `--csv` 指定時は YAML の `data` を無視する。同じ YAML を使い回す際に消し忘れた `data` があっても CSV が
  優先される。
- 将来 OCCURS・再定義・raw を CSV で扱いたくなった場合、入れ子やマップを表す追加規約（複数列展開・特殊
  接頭辞など）が要る。本 ADR はそれらを意図的にスコープ外とし、必要時に別途判断する。
