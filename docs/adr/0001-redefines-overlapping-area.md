# REDEFINES を「重なり領域 ＋ data 1 スロット」で表現する

cobdt は record 定義を葉項目の線形リストにフラット化し、サイズを順に足してオフセットを決め、`data` を位置対応で読む。REDEFINES はここに初めて「同一バイトの複数解釈（重なり）」を持ち込むため、(1) 再定義領域は `RecordLength`・dump のオフセット前進で一度だけ数える、(2) 原定義と全再定義項目は同一バイト数を必須とする（揃えたいときは FILLER）、(3) `data` 行では再定義領域を常に 1 スロットとし、原定義はネストリスト、再定義は `{target, value}` で書き分ける、と決めた。

代替として「再定義領域を複数スロットのまま位置対応で扱う」案もあったが、解釈ごとに葉の数が変わり位置対応が破綻するため退けた。サイズ可変（領域＝最大、末尾パディング）も検討したが、埋め規約が増えるため同一サイズ必須にした。

## Consequences

- create は旧来の値カウント検証（`len(values) == len(fields)`）をやめ、`data` 行を木構造に沿って構造的に突き合わせる方式へ変えた（再定義領域は 1 スロットとして消費する）。
- dump は再定義領域を自動選択せず、原定義と各再定義項目の解釈をすべてラベル付きで並列表示する（レコード種別による選択は行わない）。
- 同一エントリでの OCCURS と REDEFINES の併用はエラーとする。これは cobdt 都合の制限ではなく COBOL 仕様の制約で、再定義項目への `occurs`、`occurs` を持つ項目の再定義対象化のいずれも違法である。一方、再定義グループの従属項目に `occurs` を付けるのは合法であり、これは対応する。
