# コピーブック断片の入出力は明示フラグで行い、自動判定しない

`create-copybook` / `import-copybook` で、01 レベルのレコード行を持たない**コピーブック断片**
（`docs/CONTEXT.md`「コピーブック断片」参照）を扱えるようにした。レコード全体を包む 01 集団項目を
プログラム側に置き、その中身を断片として切り出して COPY 句で埋め込む現実の運用に対応するためである。

このとき断片かどうかを**明示フラグで表明させ、自動判定しない**と決めた。

- `create-copybook --start-level N`: フラグが**有る**ときだけ 01 を出さず N（2〜49）始まりの断片を生成する。
  無ければ従来どおり 01＋03 始まりの完全なコピーブックを出力する。
- `import-copybook --fragment`: フラグが**有る**ときだけ 01 を持たない断片を受理する。無ければ従来どおり
  01 始まりを要求する。断片モードで 01 レベルが一つでも現れたらエラーとする。

`import` 側では「先頭が 01 でなければ黙って断片とみなす」自動判定も検討したが、退けた。これは
[ADR 0002](0002-import-copybook-strict-subset.md) の "表現できないものは best-effort せずエラーで止める"
方針を、未対応**構文**だけでなくレコードの**構造**にも拡張する判断である。先頭行が欠けた／途中で切れた
コピーブックを渡されたとき、自動判定では「これは断片だ」と解釈して本来あるはずの項目を欠いた YAML を
黙って生成してしまう。これはまさに ADR 0002 が避けたかった "静かに壊れたデータ" のシナリオであり、
利便性より fail-loud を優先した。

## Consequences

- フラグの非対称（`create` は開始レベルを受け取る `--start-level N`、`import` は断片かどうかだけの
  `--fragment`）は意図的である。開始レベルは `create` では「出力時に選ぶ」ものだが、`import` では
  コピーブックのファイルから読み取るため指定不要だからである。
- 断片には 01 レコード名が存在しないため、`import-copybook --fragment` の生成 YAML の `name` は
  `--name NAME`（既定 `DATA-RECORD`）で与える。
- 生成レベルが COBOL の上限 49 を超える場合はエラーで中断する。このガードは断片モードだけでなく、
  従来の 01／03 始まりモードにも効かせる（数値の取り違えで不正な COBOL を吐かないため）。
- 断片の往復（`create-copybook --start-level N` → `import-copybook --fragment`）は構造を保つが、
  レコード名（01 の名前）は断片に含まれないため往復では保存されない。
