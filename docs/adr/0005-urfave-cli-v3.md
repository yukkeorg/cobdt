# コマンドラインパーサに urfave/cli v3 を採用する

各サブコマンドの出力先指定を位置引数から `-o`/`--output` オプションへ統一する
（指定なしは標準出力）にあたり、コマンドラインパーサを標準ライブラリ `flag` から
`urfave/cli` v3 へ置き換えると決めた。短縮形 `-o` と長形 `--output` を別名として
自然に書け、フラグと位置引数の混在順序も縛られないためである。

標準 `flag` のまま続ける案も検討した。利点は外部依存ゼロである。しかし `flag` は
`-output` と `--output` は通っても `-o` という別名を自動では持たず、`-o` と `--output`
を両立させるには同一変数を指す 2 フラグを手動で束ねる必要がある。さらに最初の非フラグ
引数で解析を打ち切るため、`cdm create config.yaml -o out.dat` のようにフラグを後置できず
順序が硬い。サブコマンドごとにこの束ね処理と順序制約を抱えるより、別名・サブコマンド構造・
順序自由を備えたライブラリに寄せるほうが、今後フラグを増やしても破綻しにくいと判断した。

`spf13/pflag` も候補だったが、サブコマンド構成（`create` / `dump` /
`create-copybook` / `import-copybook`）とヘルプ生成までまとめて担える urfave/cli を選んだ。

## Consequences

- 既存の外部依存は yaml と x/text のみだったところに、CLI フレームワークという比較的
  大きな依存が加わる。覆すには CLI 層の作り直しが要る。
- `app` 層の処理本体は CLI フレームワークに依存させない。urfave/cli の関心事は cmd
  （Action）層に閉じ込め、`app` 関数は「データ用 Writer + 診断用 Writer」を受け取る
  純粋関数に保つ（将来パーサを差し替えても `app` は無傷）。
- ヘルプ・usage は urfave/cli が自動生成する。各フラグ・コマンドの説明文は引き続き
  日本語で記述する。
