# cobdt

YAML で記述したレコード定義をもとに、COBOL の固定長データファイルの作成（create）・ダンプ（dump）・コピーブック生成（create-copybook）を行うコマンドラインツール。本書はその語彙を定義する。

## Language

**再定義**:
直前に定義済みのデータ項目と同じバイト領域を、別の項目定義で重ねて解釈すること。領域は増えず解釈だけが増える。レコード種別によって後続の意味が変わるレイアウトを表す。
_Avoid_: オーバーレイ（REDEFINES は COBOL のキーワードとして使うが、概念名は「再定義」）

**原定義**:
再定義される側の、最初に現れる項目定義。その領域のバイト数を決める基準。
_Avoid_: 元定義、被再定義項目

**再定義項目**:
`redefine` で原定義を指し、同じ領域を別の意味で解釈する項目。1 つの原定義を複数の再定義項目が指してよい。

**再定義領域**:
原定義と、それを指す再定義項目群が共有するバイト領域。原定義と全再定義項目は同一バイト数でなければならない（揃えたいときは FILLER でパディングする）。

**レコード種別**:
レコードのどの解釈（原定義か、どの再定義項目か）が有効かを実質的に決める区別用の項目。区別は本来プログラムロジックが行うため、ツールは種別から解釈を自動選択しない。
_Avoid_: 区分コード、レコードタイプ

**解釈の選択**:
テストデータ作成時に、再定義領域をどの定義で埋めるかを data 行ごとに選ぶこと。再定義領域は data 行で常に 1 スロットを占め、原定義ならネストリスト（単一基本項目ならスカラ）で値を、再定義項目なら `target`（対象項目名）と `value`（その値）で指定する。

## 表意定数

**表意定数**:
特定のバイトパターンで項目全体を埋めることを表す COBOL の予約語。`value` やデータ値に単独で書ける。
文字埋め系（ZERO・SPACE）とバイト埋め系（LOW-VALUE・HIGH-VALUE）がある。
_Avoid_: 定数（通常のリテラルと混同しない）

**文字埋め**:
項目の型に応じた「文字」で埋めること。ZERO は数字（数値項目はゼロ、X は '0'、N は全角ゼロ）、
SPACE は空白（X は半角空白、N は全角空白）で埋める。型によって埋める文字が変わる。

**バイト埋め**:
型に関係なく、項目のバイト長ぶんを同一のバイト値で埋めること。LOW-VALUE は最小値（全バイト 0x00）、
HIGH-VALUE は最大値（全バイト 0xFF）。dump では全バイトが一致する項目だけを LOW-VALUE / HIGH-VALUE と
ラベル表示し、それ以外は型に従って復号する。

## コピーブック

**コピーブック断片**:
01 レベルのレコード行を持たず、従属項目だけを記述したコピーブック。レコード全体を包む 01 の集団項目はプログラム側で定義し、その中身をこの断片として切り出して COPY 句で埋め込む運用を前提とする。通常のコピーブックが 01 で始まるのに対し、断片は任意のレベル番号（2〜49）から始まる。
_Avoid_: フラグメント、部分コピーブック

## Example dialogue

> **開発者**: この再定義領域、原定義は人物情報で 13 バイト。会社情報の再定義項目は 7+6 で 13 バイト。同じだから OK ですね。
> **ドメインエキスパート**: そう。同一バイト数でないとエラー。揃わないときは短いほうに FILLER を足す。
> **開発者**: dump したら、人物として書いたレコードも会社として書いたレコードも区別できますか？
> **ドメインエキスパート**: ツールはレコード種別から自動では選ばない。同じバイトを原定義の解釈と全再定義項目の解釈、両方ラベル付きで並べて見せるだけ。どれが正しいかは種別を見て人が判断する。
> **開発者**: テストデータで会社レコードを作るときは？
> **ドメインエキスパート**: その行の再定義領域スロットに `{target: 会社情報, value: [...]}` と書く。原定義のままでよければネストリストで値を並べるだけ。
